# Ticket 44: HOISA ブランド化 + トップページ / ヘッダー刷新

## 概要

サイト名を **「HOISA」** (確定) に変え、デザイン案 `s1.png` (相談用の画像。リポジトリには入れておらず削除済み) をもとに
**ヘッダー** と **トップページのヒーロー** を作り直す。

- トップの **Pick Up (6 記事) はそのまま残す**。ヒーローの下に続ける
- 作り直すのは「ロゴ + キャッチ + 風景写真」の部分と、その下の **3 つの枠**
  (特集 / レポート / まちのお知らせ)
- ヘッダーは全ページ共通なので、トップ以外の見た目も変わる

## 方針・決定事項

| 項目 | 決定 |
|---|---|
| サイト名 | **HOISA**。公開される名前はサイト全体で揃える (title / OG / JSON-LD / ヘッダー / フッター / LP / 通知メール / AI プロンプト) |
| キャッチ | 「飯田下伊那のあれこれを、運ぶ。」 |
| ヒーローの範囲 | ロゴ部分 + 3 つの枠。その下に既存 Pick Up |
| ヘッダー | デザイン案どおりのプルダウン型に作り直す (紗代さんの意向) |
| 素材 | 風景写真・ロゴは**まだ無い**。写真は仮置き → 後で差し替え。ロゴは明朝体の文字 + 枝の飾りを SVG で再現 |
| 運営者表記 | 著者は引き続き本岡紗代。FUNE (Instagram 名) の扱いは変えない |

## 確認が必要な点 → 2026-10-14 すべて案どおりで確定

補足: 3 は「情報を届ける」を押すと `/request/post` と `/request/interview` を選べる形 (仮)。
6 は**まだ公開しない**。一般の人には「現在開発中・近日公開」と表示する (管理者は今までどおり使える)。

1. **ヘッダーのメニュー構成** — 案:
   - 「記事を読む ▾」: 新着の記事 (`/blog`) / よく読まれている記事 (`/blog?sort=popular`) / 写真から探す (`/gallery`)
   - 「探す ▾」: 6 カテゴリ (食・グルメ / イベント・講座 / おでかけ / 文化・歴史 / 暮らし / 人・活動) + キーワード検索 (`/search`)
   - 「AI で探す」: `/chat`
   - 現在の「ホーム」は削除 (ロゴがトップへのリンクを兼ねる)
2. **About の置き場所** — 案: ヘッダーからは外し、**ヒーロー説明文の下に「HOISA について」リンク** + フッター + スマホメニューに置く
3. **「取材を依頼」の置き場所** — 今はヘッダーの主役ボタン (有料の窓口)。デザイン案には無い。
   案: 「情報を届ける」ボタンを押すと 2 択 (投稿記事で届ける / 取材を依頼する) が開く形にして、ヘッダーから消さない
4. **3 つの枠に何を出すか** — 案:
   - **特集**: おすすめ (`is_featured`) の最新 1 件。無ければ最新記事
   - **レポート**: 特集の次に新しい記事 1 件
   - **まちのお知らせ**: 「イベント・講座」の記事を 3 件 (開催日が近い・今後のものを優先)
   - 特集・レポートに出した記事は、下の Pick Up から外して重複させない
5. **「特集」「レポート」のラベル** — 今のサイトに記事の種類としては無い。枠の見出しとして固定文言で出す案
6. **「AI で探す」** — AI チャットは今、管理者専用 (一般の人にはお試し表示)。
   ヘッダーの目立つ位置に置くので、一般公開するか / お試し表示のままにするか
7. **カードの「AI 要約で読む」** — 案: さくっと / ほどよく / じっくり を押すと、記事ページへ飛んでその長さの要約が開いた状態で表示
   (要約が未生成の記事では出さない)

## 実装ステップ (小さく分けて、各ステップで画面確認 → コミット)

### Step 1: サイト名を HOISA に (見た目の大きな変更なし)
- `src/lib/site-config.ts` の name / title / description / keywords を HOISA 用に
- `Sayo's Journal` の直書き 約 20 箇所を `SITE_CONFIG.name` 参照か HOISA に置換
  (LP 3 本 + thanks / 同意文言 / `mailer.ts` 件名 / `knowledge-generator.ts`・`mini-article-prompt.ts`・タグ生成の AI プロンプト / About / Privacy / JSON-LD)
- 未使用の `src/components/ai/ChatHeader.tsx` は削除

### Step 2: フォントとロゴ
- LP 用にだけ読んでいる明朝体 (Shippori Mincho / Cormorant Garamond) をサイト共通でも使えるようにする
  (next/font で読み込み済みのものを共有化。二重読み込みしない)
- `HoisaLogo` コンポーネント (SVG の枝飾り + 文字)。ヘッダー用の小サイズとヒーロー用の大サイズ

### Step 3: ヘッダー刷新
- ロゴ + キャッチ / プルダウンメニュー / 「情報を届ける」ボタン / 検索欄
- プルダウンはキーボード操作・Esc で閉じる・外側クリックで閉じる (アクセシビリティ)
- スマホは開閉メニュー内に同じ項目を縦に並べる
- カテゴリ一覧は DB から取得 (ハードコードしない = 今日のような再編に追従)

### Step 4: ヒーロー (ロゴ部分)
- 桜 + 風景写真の背景、大きな HOISA ロゴ、説明文 2 行、右上の手書き風コピー
- 写真は**仮置き**: 公開記事の中から風景写真を 1 枚借りる (権利が確実なため)。
  後で差し替えやすいよう 1 箇所で定義
- 装飾の曲線・花びらは CSS / SVG のみ (framer-motion 不使用の方針どおり)

### Step 5: ヒーロー (3 つの枠)
- 特集 (大カード) / レポート (中カード) / まちのお知らせ (リスト 3 件 + もっと見る)
- 記事データの取得はトップの既存クエリと 1 本化 (Pick Up との重複除外)
- 「AI 要約で読む」から記事ページの要約へ (`SummarySlider` に初期レベルを渡せるようにする)

### Step 6: フッター・周辺
- フッターのブランド名 / キャッチ / サイトマップを新メニュー構成に合わせる
- OG 画像 / favicon は素材が揃ってから (今回は対象外)

### Step 7: 仕上げ
- 375px〜1920px で表示確認 (スマホでヒーローが縦長になりすぎないか)
- Lighthouse で画像の LCP を確認 (ヒーロー写真は `priority` 指定)
- CLAUDE.md / `.claude/rules/frontend.md` / `implementation-status.md` 更新

## 影響範囲・注意点

- ヘッダー変更は**全公開ページ**に出る。LP 2 本 (`(lp)` グループ) は独自ヘッダーなので影響しない (ブランド名の置換のみ)
- トップは ISR 600 秒のまま。3 つの枠のデータも同じ revalidate に乗せる
- 「まちのお知らせ」は今は記事から作る。将来イベントカレンダーができたら、そちらに差し替える前提
- デザイン案のサンプル記事 (里山の畑・たかぎの朝市など、2024 年の日付) は実在しないので、実際の記事で埋まる

## 実施結果メモ (2026-10-14)

- **フォントの事故と対処**: Step 2〜4 で和文明朝 (Shippori 4 ウェイト) と手書き風 (Klee One) を next/font/google で
  サイト全体に読んだところ、トップがフォントだけで 13MB / 482 リクエスト、モバイル LCP 89 秒になった
  (和文は表示した文字ぶんの unicode-range 分割ファイルを落とすため)。使う場所は固定文言だけなので、
  その文字だけのサブセットを `npm run fonts:subset` で作り next/font/local に切り替え。LP の Shippori は LP 限定に戻した
- **計測** (ローカル本番ビルド, Lighthouse 12): モバイル Performance 84 / LCP 4.2s / CLS 0、デスクトップ 99。
  改修前の本番トップはモバイル 76
- **残る技術的負債**: 既存の Noto Serif JP / Noto Sans JP (各 3 ウェイト) の @font-face CSS が各 ~280KB、全ページで描画ブロック。
  改修前からあるもの。減らすならウェイト削減かサブセット化 (別チケット)
- **確認した幅**: 375 / 390 / 768 / 1024 / 1100 / 1440 / 1920px。全ページ横スクロール (はみ出し) なし
- **公開後の修正 (2026-10-14, `1a19047`)**: 15 インチのノート PC (1280〜1440px) で記事ページ右の目次が本文・画像に重なっていた
  (目次は 1280px から出していたが、本文の横に並べるには 1440px 必要)。目次とヘッダーのキャッチを 1440px からに変更
