## 実装メモ (決まったら詰める)

- **② 更新履歴**: 新テーブル (例 `post_updates`: post_id / 日付 / 内容 1 行)。記事編集画面の保存時に「何を更新したか」を任意で書くと履歴に足す。
  案: **履歴を書いたときだけ公開側の「最終更新」を新しくする** (誤字修正では変えない)。今は本文などを変えて保存すると必ず `updated_at` が変わる
- **③ 季節の最新情報**: 記事ごとの任意の枠 (見出し + 本文)。空なら出さない。本文の上 (要約の近く) に表示。季節が過ぎたら消す運用
- **⑥ 最近更新された記事**: 履歴の新しい順。置き場所 (トップ / 記事ページの横 or 下) は要相談
- 日付だけの更新は効果が無く、繰り返すと Google がサイトの更新日を信用しなくなる → 紗代さんには「中身を足してから保存」と伝え済み

## 決まった仕様 (2026-11-14)

- **記事の頭**: パンくず → 種類バッジ → **タイトル → 初回掲載 / 最終更新** (+ 閲覧数) → カテゴリ → **写真**。日付は `2026.5.12` (日本時間)
- **更新履歴** (`post_updates`: post_id / updated_on (date, JST) / note 100 字まで, migration `20261114120000`)
  - 管理: 記事編集 (編集時のみ) の本文の下に「更新履歴」カード。行の追加・日付・内容・削除 → 記事の「保存」でまとめて delete → insert
  - 公開: 写真の下に帯「この記事は随時情報を更新しています」+ 最新の 1 行 +「更新履歴を見る」(押すと本文の後ろの更新履歴へなめらかにスクロール)。本文 (折りたたみ) の外・タグの上に更新履歴。最後に「初回掲載」の行を自動で付ける。更新履歴の枠は全記事に出す (履歴が無ければ「初回掲載」の 1 行だけ。DB には入れず公開日から作る)。帯は 1 回でも更新した記事だけ
  - **「最終更新」= 履歴の最新日** (初回掲載日より後のときだけ表示)。誤字直しの保存では変わらない。dateModified・og:modified_time・サイトマップの lastmod も同じ日付 (`contentModifiedAt`)。`posts.updated_at` は管理用にそのまま
- **最近更新された記事**: 記事ページの関連記事の下に最大 3 件 (履歴の新しい順・自分と終了イベントは除く・「最終更新」が出ている記事だけ)。記事ページは ISR 1 時間なので、更新してから他の記事のページに並ぶまで最大 1 時間
- ロジックは `src/lib/post-updates.ts` (+ テスト)
